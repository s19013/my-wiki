# 解説書: Bitnami から Docker Compose への移行（2026-10）

2026 年 10 月に、本番サーバーを Bitnami LAMP（PHP 8.0）から Docker Compose（PHP 8.2）へ作り直した。
これはそのときの記録で、**何をしたか** と **なぜそうしたか** を後から学び直せるように書いている。

日々の操作手順（デプロイ・復元・作り直しのコマンド）は [../README.md](../README.md) にある。
この解説書は「考え方」と「経緯」の担当。

## 全体の流れ（1 枚で）

```
[調査]  旧サーバーを読み取り専用で調べる
          → PHP 8.0 はその場で上げられない（Bitnami）
          → バックアップが 3 年半ずっと空だった、など問題が見つかる
   ↓
[計画]  「Docker で作り直し、設定をすべてコードにする」と決める
          Laravel 9 はそのまま → PHP は Laravel 9 が動く 8.2 系
   ↓
[保全]  旧サーバーのスナップショットと、中身のある DB ダンプを取る   ← 何よりも先に
   ↓
[段階1] ローカルで Docker 構成を作り、本番ダンプで動作確認        → コミット
[段階2] バックアップ・復元スクリプトを作り、往復できるか確認        → コミット
[段階3] 新しい Lightsail を作り、本番と同じ設定でデプロイ・確認    → コミット
[段階4] 運用手順書（../README.md）                                   → コミット
   ↓
[切替]  旧サーバーをメンテナンスモード → 最新ダンプを移す → 静的 IP を付け替え
   ↓
[後片付け] 様子を見て main にマージ、旧サーバーを削除
```

## この移行で大事にしたこと

1. **調べる前に変えない。** 最初は読み取り専用のコマンドだけで現状を把握した。
2. **壊す前に守る。** どの作業よりも先に、スナップショットと DB ダンプを取った。
3. **小さく進めて、毎回確かめる。** 段階ごとに動作確認し、通ったらコミットした。どの段階でも 1 つ前に戻せる。
4. **設定はすべてコードに残す。** 「どういう設定をしたか覚えていない」状態を二度と作らないため。
5. **「動いているはず」を信じない。** バックアップは、復元できることを確かめて初めてバックアップと言える。

## 用語メモ

| 用語 | 意味 |
|---|---|
| Bitnami | PHP・Apache・MariaDB を 1 つにまとめた配布物。Lightsail の「LAMP」の中身。PHP だけを上げることができない |
| イメージ / コンテナ | イメージは「設計図から作った完成品の型」、コンテナは「その型から起動した実物」。コンテナは消しても、イメージから同じものを何度でも作れる |
| volume | コンテナを消しても残る保存領域。DB のデータやセッションを置く |
| Docker Compose | 複数のコンテナ（app・caddy・db）の構成を 1 つの YAML に書き、まとめて起動する道具 |
| リバースプロキシ | 外からのリクエストを受けて、内側のサーバーに渡す役。ここでは Caddy |
| ACME / Let's Encrypt | 無料の SSL 証明書を自動で発行する仕組み。Caddy が自動でやってくれる |
| 静的 IP | インスタンスに付け外しできる固定 IP。DNS はこれを向いているので、付け替えるだけで移行できる |
| user-data | インスタンスの初回起動時に自動で実行されるスクリプト |
| 冪等（べきとう） | 何回実行しても結果が同じになること。setup-server.sh はそう作ってある |
